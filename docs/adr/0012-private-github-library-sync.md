# ADR 0012：以白名单快照和三方合并实现可选私有 GitHub 同步

- 状态：接受
- 日期：2026-10-04

用户需要在多设备共享普通资料库，同时保留本地优先、私密库可见性和现有 Skill 文件包。不能复用含私密资产的 createBackup，也不能采用最新时间戳覆盖两端。

使用专用个人私有仓库和独立细粒度 Contents 读写 Token；每次写入前验证仓库为 private 且 owner.type=User。存储固定白名单格式文件，通过 Contents SHA compare-and-swap，409/422 重读，正常 Git 提交保留历史。超过 Contents 内联范围用 blob 读取；JSON 固定 15 MiB 上限而非声称无上限包同步。

稳定资产/分类 ID、精确本地确认基线、持久删除标记进行三方比较。冲突独立保存，分类冲突重映射远端引用。普通→私密在资产保存事务中持久记录仅含 ID 的本地撤回标记，随后发布权威撤回标记；即使私密条目在下次同步前被删除或移回普通库也不丢失，不同步私密内容；远端离线修改仅保留为本地私密 AIGC 冲突。私密→普通使用新 ID。未曾公开的私密 ID 不出现在远端。

上传的最后 revision/private 检查和 PUT 使用现有写锁，最终 pull 也使用 applyDatabaseChange，配置保存/移除同锁并取消旧任务。短暂网络等待可能使其它保存等待或提示忙，8 秒单请求超时避免无限锁持有。自动同步不作为保存成功的前提；7 秒 worker 防抖配合 30 秒报警和 5 分钟巡检。

精确基线会重复普通资产及包内容，申请 unlimitedStorage，避免原10 MiB配额破坏承诺。同步包用不可变本地 ID；异常中间阶段可能留下无引用包。持久 tombstone 不自动压缩，长期离线设备的删除安全优先；库过大时明确失败，可继续本地使用。撤回不删除原 Git 历史，与私密库防止随手查看的产品边界一致。
