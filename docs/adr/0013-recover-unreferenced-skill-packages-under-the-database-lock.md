# ADR 0013：在资料库写锁内恢复和清理无引用 Skill 文件包

状态：已采纳

## 背景与方案选择

资产 JSON 与 IndexedDB 文件包不具备共同事务。进程可能在写包后、保存引用前中断；更新、删除或失败回滚的清理也可能失败。之前只在当前操作中尽力清理，重启后无法发现遗留包。见 [issue #11](https://github.com/star-736/Prompt-Plugin/issues/11)。

比较单独的小型操作日志、按时间延迟删除和扫描包库存：日志会新增另一份需要与文件包及引用协调的持久状态；单纯延迟不能证明操作已经结束。本轮选择已有包记录作为持久准备记录，扫描 ID 库存并在既有资料库写锁内判断引用，不新增存储键、IndexedDB 版本或备份字段。

## 生命周期与协调边界

- 准备：收集、更新、导入和同步都在 `applyDatabaseChange()` 的资料库写锁内写入完整包，再保存资产引用。包一旦被资产引用，不覆盖其内容；更新使用新的包 ID。
- 已引用：最新资产的 `skillPackage.packageId` 是确认依据。所有资产引用均受保护，不按类型、隐私或单一条目筛选；同步基线已内嵌文件内容，无额外包 ID 引用。
- 待清理：持久包记录存在且锁内最新资料库没有引用。没有活动写入者时可清理；清理与包准备使用同一个 `futurecontext.v1:write` 锁，因此不会删除仍在准备的包。
- 恢复：后台每次 Service Worker 加载、浏览器启动或扩展安装/更新时重新建立五分钟恢复报警并扫描；报警再次扫描。只读取 IndexedDB 的包 ID，不加载所有文件内容。上下文中断会释放 Web Lock，重启后重新根据持久引用判断，已确认引用的包保留，无引用的准备包清理，不自动发布未保存资产。
- 更新、删除和失败回滚的即时清理重新取得写锁、读取最新引用，不使用保存时的旧快照。导入重试已经处于写锁内，按该轮最新引用清理上一轮准备包。同步成功、失败或取消后同样按最新引用清理旧包和本轮准备包。
- 删除失败保留原包记录，下次扫描重试；读库、读取库存或获取写锁失败均不继续清理。更新版本的只读资料库跳过全部清理。清理失败不会把已确认资产提交误报为失败，也不改变同步成功状态。

`package-store.js` 的读写方法是底层存储适配器。生产包写入必须在资料库写锁内进行；不能从锁内嵌套申请锁。`persist` 注入仅用于独立存储适配器的兼容测试，不提供跨上下文协调；实际扩展路径使用 `storage` 与统一写锁。无锁或绕过协议的外部写入不属于安全清理保证。

这不是跨库原子事务，也不恢复丢失的包内容；只为可识别的无引用包提供幂等清理。关闭浏览器、worker 休眠或调度延后会推迟清理，不承诺精确清理时间。
